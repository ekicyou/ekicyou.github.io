# Implementation Plan

> 基準の置き場: OS の一時フォルダ(Windows では `%TEMP%`)の下の `posts-archive-folder-baseline/`。公開パスの一覧は `paths-before.txt`、成果物の写しは `dist-before/`。1.2 が作り、3.3 と 4.2 が使う。
>
> 突き合わせの合格の決まり(3.3・4.2): `verify` の基準比較の出力に `消えるパス(0 個)` と `増えるパス(0 個)` がそのまま出ていること(このコマンドの終了コードは常に 0 なので、出力で判断する)。`git diff --no-index --stat` が何も出さず、終了コードが 0 であること。

- [x] 1. 準備: 依存を入れ、仕組みを変える前の成果物を基準として取っておく
- [x] 1.1 依存を入れ、今のままでビルドと確かめが通ることを確かめる
  - ワークツリーの `site/` には依存が入っていないので、`npm ci` で入れる(版はロックファイルのまま。新しい依存は足さない)
  - 何も変えていない姿で `npm run check`・`npm test`・`npm run build`・`npm run verify` を走らせる
  - 4 つとも誤りなしで終わり、`site/dist/` ができている
  - _Requirements: 5.1_
- [x] 1.2 移動の前の基準(公開パスの一覧と成果物の丸写し)をリポジトリの外に作る
  - 仕組みも原稿も変えていない 1.1 のビルドの成果物を使う。コードを変えた後に作り直してはならない
  - 公開パスの一覧を、`verify` の一覧出力で基準の置き場の `paths-before.txt` へ書き出す(書き出しは Git Bash か PowerShell 7 で行う。Windows PowerShell 5.1 のリダイレクトは UTF-16 になり、基準比較が読めない)
  - 同じ成果物を、基準の置き場の `dist-before/` へ丸ごと写す
  - 基準の置き場に `paths-before.txt` と `dist-before/` があり、リポジトリの中には何も増えていない(`git status` がきれい)
  - _Requirements: 5.1, 5.3_

- [x] 2. 記事の URL の決まりを、フォルダに置いた記事に広げる
- [x] 2.1 記事の識別子のフォルダの部分を読み飛ばし、ファイル名だけで日付・名前・公開パスを決める
  - 識別子の最後の区切りより後ろをファイル名として、今までと同じ検査(形、日付、`index` の禁止)を掛ける。フォルダを理由に止める検査と、その理由の文は消す
  - 決まりに合わないときの誤りの文には、フォルダを含む識別子をそのまま入れる
  - 先頭のコメントを「識別子はフォルダを含んでよい」に直す
  - 単体テスト: 「サブフォルダを拒む」テストを消す。フォルダつき(1 段・2 段)の識別子が直下と同じ結果になり、公開パスと名前にフォルダ名が入らないこと、今あるテストの識別子に `archive/` を付けても同じ公開パスになること、フォルダつきで決まりに合わない識別子がフォルダつきの識別子を含む誤りを投げることを確かめる
  - 公開後の確かめ(変えない)が渡す形 `archive/…` で公開パスが決まり、決められないときの誤りの文がフォルダを含むことを、コードの読み合わせで確かめる
  - `npm test` が通り、テストの中に「サブフォルダ」を拒むテストが残っていない
  - _Boundary: PostPath, PostPathTest_
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 1.7, 3.1, 3.3, 3.4, 3.6_
- [x] 2.2 同じファイル名の記事の組を見つけて、すべての場所を挙げて止める検査を足す
  - 識別子の並びを受け取り、ファイル名を大文字・小文字を区別せずに比べ、2 本以上の組があれば、すべての組のすべての識別子を挙げて誤りを投げる。組の中も組同士も文字の符号の順に並べる。誤りの文の形は設計書のとおり
  - ASCII の外の大文字・小文字の扱いの限りを、`shortcut:` のコメントで残す
  - URL の決まりと同じく、生成ツールに依らない場所に置く
  - 単体テスト: 重複なし(直下とフォルダの混在・空の並び)で投げない。直下とフォルダ、違うフォルダ同士、3 本、2 組、大文字・小文字だけ違う場合に投げ、すべての識別子が文に入る
  - `npm test` が通る
  - 2.1 と同じファイルを触るので、2.1 の後に行う
  - _Boundary: UniqueFileNames, PostPathTest_
  - _Requirements: 2.1, 2.2, 2.4, 3.5_

- [x] 3. 検査を全記事に掛け、文書を合わせ、仕組みだけの変更で成果物が変わらないことを確かめる
- [x] 3.1 記事の一覧を作るところで、非公開の記事も含めた全記事を重複の検査に通す
  - 2.2 で足した重複の検査を使う
  - 公開中の記事に絞り込む前の全記事の識別子を、ファイル名の形の検査の直後に、重複の検査へ渡す
  - 並べ方・絞り込み・前後の記事の求め方は変えない
  - コレクションの定義のコメントを、識別子がフォルダを含みうる形に直す(コードは変えない)
  - 絞り込みより前に検査を呼んでいることを、コードの読み合わせで確かめる(このファイルは単体テストに掛からない)
  - `npm run check` と `npm run build` が誤りなしで終わる
  - _Boundary: PublishedPosts_
  - _Depends: 2.2_
  - _Requirements: 1.4, 1.6, 2.1, 2.3, 5.4_
- [x] 3.2 (P) steering の記事の置き方の記述を、新しい決まりに書き換える
  - 記事の節: どのフォルダにも置けること、URL はファイル名だけで決まること、古い記事は `archive/`・新しい記事は直下・さらに移すのは手作業で足りること、同じファイル名(フォルダ違い・非公開・大文字小文字違いも)で止まること、フォルダ `archive/` とページ `/archive.html` は関係が無いこと
  - ファイル名の決まり: 「サブフォルダに置かない」を消し、「下のフォルダに置いてよい。同じファイル名は置けない」に替える
  - 文書(`doc`)の節は変えない
  - steering・`CLAUDE.md`・`README.md` を「サブフォルダ」で探して、改めた決まりの記述が 1 つも残っていない
  - _Boundary: StructureDoc_
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5_
- [x] 3.3 仕組みの変更だけで、成果物が基準と変わらないことを確かめる(確かめだけのタスク)
  - 基準の置き場が無ければ、作り直さずに止まって報告する
  - `npm run check`・`npm test`・`npm run build`・`npm run verify` を走らせる
  - 基準と、公開パスの一覧と成果物の中身を突き合わせる(合格の決まりは冒頭のとおり)
  - 2.1〜3.2 の変更がすべてコミット済みで、そのどのコミットにも `site/src/content/posts/` の下の記事が入っていない(push しない)
  - 4 つの確かめが通り、突き合わせが合格の決まりを満たす
  - _Depends: 1.2_
  - _Requirements: 3.2, 5.1, 5.3_

- [x] 4. 古い記事を `archive/` へ移し、前後を突き合わせる
- [x] 4.1 2010 年以前の記事 399 本を `git mv` で `archive/` へ移し、移動だけのコミットにする
  - 3.3 の突き合わせが合格してから行う(今の仕組みのままで移すとビルドが止まる)
  - 記事の置き場に `archive/` を作り、年で選ぶ glob(2003〜2010 年)で、非公開の記事も含めて移す。中身とファイル名は変えない
  - 移動のコミットには 399 本の名前の変更だけを入れる。タスクの印(`tasks.md` の `[x]`)やメモは、その後の別のコミットにする(push しない)
  - 移動のコミットそのもの(`HEAD` ではなく、そのコミットを名指しする)の変更が、すべて `R100` で 399 行、2011 年以降の記事も `site/src/content/posts/` の外のファイルも含まない
  - 直下の記事の年がすべて 2011 以上、`archive/` の記事の年がすべて 2010 以下
  - _Depends: 3.3_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6_
- [x] 4.2 移動の後のビルドと確かめを走らせ、基準と突き合わせた結果を開発者に示す
  - 基準の置き場が無ければ、作り直さずに止まって報告する
  - `npm run check`・`npm test`・`npm run build`・`npm run verify` を走らせる。`verify` が誤り 0 件で、フォルダを理由にした誤りも警告も出さず、非公開の記事が隠れたまま、保つパスの一覧がすべて公開されている
  - 基準と、公開パスの一覧と成果物の中身を突き合わせる(合格の決まりは冒頭のとおり)
  - 合格なら、突き合わせの出力と `verify` の結果を報告に載せる。合格しなければ完了とせず、増えたパス・消えたパス・違うファイルをそのまま示す
  - 報告に、消えるパス 0・増えるパス 0・成果物の差なし・`verify` の結果が載っている
  - _Depends: 1.2_
  - _Requirements: 1.1, 1.4, 1.5, 1.6, 2.4, 3.2, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6_

## Implementation Notes
- 範囲の外: `npm run verify` が、移す前の基準から `/about.html` の `https://ekicyou.github.io/pasta/` を「サイト内のリンクの先が無い」と警告する(この spec の変更とは関係が無い)。
- 基準との突き合わせの `git diff --no-index` は、`-c core.autocrlf=false` を付け、標準エラーを捨てると改行の警告に埋もれない。
